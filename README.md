# SchoolX Corporate RAG Telegram Bot

Асинхронный Telegram-бот на **aiogram 3.x** для доступа к корпоративной RAG-системе на базе локального сервера **LM Studio** и векторного хранилища **ChromaDB** с CPU-эмбеддингами **FastEmbed**.

Проект спроектирован с учетом жестких ограничений VRAM (NVIDIA GeForce RTX 4070 12GB): запросы к модели выполняются строго последовательно через FIFO-очередь с concurrency=1, исключая Out-Of-Memory (OOM) и зависания драйвера.

## ⚡ Ключевые особенности и технические решения

1. **Строгая FIFO-очередь инференса (`QueueManager`):**
   - На RTX 4070 (12 GB VRAM) параллельные запросы к локальной LLM вызывают OOM.
   - `QueueManager` обрабатывает строго **1 запрос к LM Studio за раз**.
   - Если сервер занят, пользователь сразу получает сообщение:
     > *"⏳ Запрос принят. Вы в очереди: позиция 2. Пожалуйста, подождите..."*
   - При наступлении очереди бот обновляет статус и непрерывно отправляет action `typing` до выдачи ответа.

2. **Нулевой расход VRAM на эмбеддинги:**
   - Библиотека `fastembed` вычисляет эмбеддинги модели `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` **строго на CPU** с выносом в `asyncio.to_thread`.
   - Вся видеопамять 12 GB остается полностью свободной для квантованной LLM в LM Studio.

3. **Контроль доступа и интерактивная консоль администратора (`/admin`):**
   - Бот доступен только авторизованным ID (`ALLOWED_TELEGRAM_IDS` + таблица `allowed_users` в SQLite).
   - Быстрая проверка прав $O(1)$ через in-memory кэш.
   - Полнофункциональная интерактивная админ-панель: команда `/admin`.
   - Возможности консоли:
     - 📁 **Управление базой знаний**: интерактивный список всех загруженных файлов с подсчетом чанков, кнопками точечного удаления `🗑️ Удалить` и полной очистки базы с подтверждением.
     - 👥 **Управление доступом**: просмотр списка авторизованных пользователей и мгновенный отзыв доступа (бан) по кнопке `🚫`.
     - 📊 **Мониторинг**: оперативная сводка состояния очереди, инференса и оценок ответов.
   - Текстовые команды администратора:
     - `/admin` — открыть интерактивную консоль управления;
     - `/del_file <имя_файла>` — быстрое удаление файла из базы знаний;
     - `/add_user <tg_id>` — предоставление доступа;
     - `/ban_user <tg_id>` — отзыв доступа;
     - `/stats` — сводная статистика системы.

4. **Ингестия документов "на лету":**
   - Пользователь или администратор просто отправляет файл любого поддерживаемого формата в чат боту:
     - **Word:** `.docx`, `.doc`, `.docm`, `.rtf` (с извлечением текста, таблиц и разделов)
     - **Excel:** `.xlsx`, `.xls`, `.xlsm`, `.csv` (с сохранением названий листов и структуры строк)
     - **PowerPoint:** `.pptx`, `.ppt`, `.pptm` (с разбивкой по слайдам, таблицам и заметкам)
     - **Документы и текст:** `.pdf`, `.txt`, `.md`
   - Сервис `DocumentIngestionService` извлекает текстовые блоки и таблицы, разбивает документ на чанки (~500 токенов с перекрытием 50 токенов), сохраняя имя файла и номер страницы / листа / слайда.
   - Метаданные файла сохраняются в SQLite БД (`user_documents`), а фрагменты векторизуются на CPU в изолированную коллекцию ChromaDB в реальном времени.

5. **Строгий RAG-промпт и цитирование:**
   - Модель отвечает **строго** по предоставленному контексту. Если информации нет — выдается фраза: *"В базе знаний нет информации по данному вопросу"*.
   - В конце ответа автоматически выводится блок с кликабельными/наглядными источниками:
     ```text
     Источники:
     • регламент.pdf (стр./раздел: 4)
     ```

6. **Логирование качества (Feedback):**
   - Под каждым ответом прикрепляются кнопки `👍 Полезно` и `👎 Не помогло`.
   - Оценки привязываются к `log_id` в SQLite и доступны в `/stats`.

7. **Персональные настройки RAG для каждого пользователя:**
   - Для каждого пользователя (по его Telegram ID) можно индивидуально переопределять:
     - `top_k` (количество чанков поиска в персональной ChromaDB);
     - `temperature` (температура генерации LLM);
     - `max_tokens` (максимальная длина ответа);
     - `model` (модель в LM Studio);
     - `system_prompt` (персональный системный промпт / инструкция);
     - `chunk_size` и `chunk_overlap` (параметры чанкинга загружаемых документов).
   - Поддерживаются 3 удобных способа конфигурации:
     1. В конфигурационном файле `user_rag.cfg` (INI/CFG формат):
        ```ini
        [6060196826]
        top_k = 5
        temperature = 0.1
        max_tokens = 2000
        model = qwen2.5-14b-instruct-1m
        system_prompt = Ты строгий эксперт-аналитик...
        chunk_size = 400
        chunk_overlap = 40
        ```
     2. В `.env` в формате JSON:
        ```ini
        USER_RAG_CONFIGS='{"6060196826": {"top_k": 5, "temperature": 0.1}}'
        # или путь к файлу:
        USER_RAG_CONFIG_FILE=user_rag.cfg
        ```
     3. Напрямую в коде `bot/config.py` или через методы `settings.get_user_rag_config(user_id)` / `settings.set_user_rag_config(user_id, {...})`.

## 🚀 Установка и запуск

### 1. Подготовка окружения
```bash
# Клонируйте репозиторий или перейдите в папку проекта:
cd schoolX_bot

# Создайте и активируйте виртуальное окружение:
python -m venv venv
# Linux/macOS:
source venv/bin/activate
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1

# Установите зависимости:
pip install -r requirements.txt
```

### 2. Настройка конфигурации (.env)
Скопируйте пример файла конфигурации:
```bash
cp .env.example .env
```
Заполните `.env`:
```ini
BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
ADMIN_IDS=123456789
ALLOWED_TELEGRAM_IDS=123456789,987654321
LM_STUDIO_URL=http://localhost:1234/v1
LM_STUDIO_MODEL=local-model
```

### 3. Запуск LM Studio
1. Запустите **LM Studio**.
2. Загрузите желаемую модель (например, `Qwen2.5-7B-Instruct-GGUF`, `Llama-3.1-8B-Instruct-GGUF` или `Mistral-Nemo-12B`).
3. В разделе **Local Server** нажмите **Start Server** (порт по умолчанию: `1234`).

### 4. Запуск Telegram-бота
```bash
python main.py
```
Бот инициализирует SQLite, создаст коллекции ChromaDB, предзагрузит модель эмбеддингов FastEmbed на CPU и начнет прием сообщений.
